==========================================
  MINIATURE OFFICE - INSTALLATION DEMO
  Experimental Flask prototype

WINDOWS USERS:
--------------
1. Right-click: install.ps1
2. Select: "Run with PowerShell"
3. Wait for: "✅ Installation Complete!"
4. Double-click: start.bat
5. Open browser to: http://localhost:5000

   That's the local Flask UI.

MACOS USERS:
------------
1. Open Terminal
2. Run: ./install.sh
3. Wait for: "✅ Installation Complete!"
4. Double-click: start.command
5. Open browser to: http://localhost:5000

LINUX USERS:
------------
1. Open Terminal
2. Run: ./install.sh
3. Wait for: "✅ Installation Complete!"
4. Run: ./start.sh
5. Open browser to: http://localhost:5000

DOCKER (bash / WSL / Git Bash — not Windows cmd.exe):
-----------------------------------------------------
1. Open a bash-like shell
2. Generate SECRET_KEY once and reuse it. A new key on a later
   compose up cannot verify an HMAC-tagged audit JSONL already
   in ./data:
   export SECRET_KEY=$(python3 -c 'import secrets; print(secrets.token_hex(32))')
   mkdir -p user_workspace data logs
   # chmod 777 is the CD bind-mount workaround, not a default.
   chmod 777 user_workspace data logs
   docker compose up --build
3. Wait for server to start
4. Open browser to: http://localhost:5000

   Compose interpolates SECRET_KEY with no default. Production refuses
   placeholders. World state is in-memory.

DOCKER ON WINDOWS (PowerShell):
-------------------------------
$env:SECRET_KEY = python -c "import secrets; print(secrets.token_hex(32))"
New-Item -ItemType Directory -Force -Path user_workspace, data, logs | Out-Null
docker compose up --build

Reuse the same SECRET_KEY on later runs if ./data already has an
HMAC-tagged audit log. Skip chmod 777 unless the container cannot
write the bind mounts.

MOBILE/TABLET USERS:
--------------------
1. Someone starts the server (see above)
2. Find computer's IP:
   - Windows: ipconfig
   - Mac/Linux: ifconfig
3. Open phone browser
4. Go to: http://[YOUR_IP]:5000
   Example: http://192.168.1.100:5000
5. Optional: bookmark the page. "Add to Home Screen" can pin a
   shortcut. The PWA shell (manifest.json + sw.js) only installs
   from a secure context (https, or http://localhost / 127.0.0.1).
   A plain http://LAN_IP:5000 origin is not a secure context, so
   the service worker will not register there. Either way this is
   still the Flask HTML UI, not a native app.

HEADSET BROWSERS (not a VR product):
------------------------------------
1. Start server on a computer (see above)
2. Open the headset's web browser
3. Go to: http://[YOUR_IP]:5000

   You get the same Flask HTML page. There is no WebXR client.
